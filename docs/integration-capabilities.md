# X integration capabilities

Documentation reviewed November 11, 2026. The personal release targets one connected account on X's self-serve pay-per-use tier. An endpoint documented by X still needs a funded developer app, the listed scopes, and authorization for the actual account. All integration tests use provider fixtures. No live account granted a token during implementation.

## Connection and private access

Set `APP_ORIGIN` to the exact origin of the app. Register that origin followed by `/api/x/callback` in the X developer console. A local example is `http://localhost:5173/api/x/callback`. The hostname used in the browser, the configured origin and the callback must match. Set `X_CLIENT_ID`, `X_CLIENT_SECRET` and a 32-byte hex `X_TOKEN_ENCRYPTION_KEY` as server secrets. Configure a web app with read/write user-context OAuth. Connect through Settings to check the returned account. Keep the same encryption key across restarts and use a reconnect plan for rotation.

In hosted mode, configure `OWNER_USER_ID` and serve the Worker exclusively behind the trusted private Sites identity dispatcher, which removes client-supplied identity headers. Direct exposure of the Worker would remove that trust boundary. Local Vinext development uses the starter's loopback-only simulated sign-in. The local user ID is `local_seedy`. The local middleware strips incoming identity headers and checks the client address. Connecting X remains a separate OAuth flow. [X authentication](https://docs.x.com/fundamentals/authentication/overview)

Disconnect removes the encrypted credentials immediately and attempts upstream revocation. Submissions already in flight may finish. Saved drafts, notes, opt-outs, snapshots and minimal account IDs remain until workspace deletion. A reconnect to the same X ID recovers the same stored identity and opt-outs. A workspace purge removes stored content, media, credentials and grant states and retains only the aggregate billing reservations needed by the local cap. Revocation can also be completed in X Connected apps.

## Pricing and restrictions

Prices are USD estimates. The registry uses integer microdollars. X lists $0.015 for a plain original, $0.200 for a post containing a URL and $0.010 for a summoned reply. The summoned-plus-URL precedence remains unclear, so that operation is gated. Generic reads cost $0.005 per post and $0.010 per user. Owned timelines and mention reads can qualify for $0.001 per returned resource when the queried user, authenticated user and developer-app owner match. Configure `X_DEVELOPER_OWNER_ID` server-side only after verifying it in the developer console. Otherwise the full read rate applies. Author expansions reserve up to one user per returned mention. The app estimates from returned resources and does not assume billing deduplication or apply free credits. [X pricing](https://docs.x.com/x-api/getting-started/pricing)

X groups deletion and content-management rates without mapping the delete-post endpoint unambiguously in its public pricing table. An administrator must check the console and set a positive conservative `X_DELETE_COST_MICROS` before deletion is enabled. Every deletion also reserves $0.005 to verify authorship. `X_DELETE_BATCH_LIMIT` can lower the default maximum of three. Keep provider spending limits active since the local ledger tracks estimates. [X pricing](https://docs.x.com/x-api/getting-started/pricing)

For live verification, authenticate to the developer console, review the app owner and rate map, fund the desired budget, connect with the requested scopes and run a small approved read. Independently verify any additional media or thread entitlement before extending the policy. Publication, deletion and written AI reply permission require separate owner authorization.
